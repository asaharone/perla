# Perla Helsa E-com — аналитика по ТЗ (блоки 1–8)

Страница для e-com PM, маркетинга и финансов: восемь блоков ТЗ на e-com аналитику, сверка источников и словарь
определений v1. Собирается из девяти витрин BigQuery и 23 запросов-блоков, без ручного ввода.

Опубликовано (claude.ai): **https://claude.ai/artifact/7RmB8prsCLmNS24dG1nnnv** · страница-сестра для Борда —
Perla Helsa Cockpit: https://claude.ai/artifact/NcxzZ4dozRDuNuttH2Hg17.

Данные: январь–сентябрь 2026, B2C Украина без B2B / PR / сотрудников, суммы в ₴. Сентябрь «дозревает»
(часть заказов в доставке, покупки за 7 дней после ATC и спасения после неудачной оплаты ещё не окончательные).

## Определения v1 (на согласование до 10.10)

Полный список — `data/definitions.json` (он же показан на вкладке «Дані й визначення»). Ключевые:

- **Заказ созданный** — сделка Zoho UA не Canceled; **успешный** — Successful / Successful/Deferred Shipment.
- **Выручка** — успешные заказы по дате заказа (страница); для плана и финансов — по дате отгрузки (daily_kpi_metrics, курс месяца).
- **План по дням** — месячный план по SKU, веса = выручка того же дня недели за 8 предыдущих недель; альтернатива «поровну» рядом.
- **Платная позиция / UPO** — строки Order, Upsell Online, Upsell Manager; подарки (Gift) отдельно.
- **Новый клиент** — первый оплаченный заказ в истории (order_num = 1); в витрине клиентов — дедупликация контактов по телефону (хранится только хеш).
- **Окно воронки** — 7 дней от ATC / корзины до purchase того же user_pseudo_id.
- **Тип входа** — по посадочной странице (regex в `00_dictionaries.sql`), до релиза page_type.
- **Место добавления в корзину** — страница события; виджет — `upsell_add_product` в те же ±5 с; после P1 — item_list_name.
- **Онлайн-оплата** — Payment_Scheme Buyout / Mixed; результат по транзакциям WFP; **спасение** — контакт КЦ или триггер eSputnik за 7 дней + оплачено/доставлено.
- **Брошенная корзина** — user × день с view_cart / begin_checkout без purchase 7 дней; сумма — по items (параметр value события = цена последнего товара).
- **Порог бесплатной доставки** — 2300 ₴, с 25.09.2026 — 2100 ₴.

## Решения до 10.10

1. Две базы заказов и база выручки (по заказу на странице vs по отгрузке у финансов) — финансы + e-com PM.
2. Правило разбивки плана по дням — финансы.
3. Определение нового клиента и окно 7 дней — маркетинг-аналитик.
4. Порог бесплатной доставки и правило автоподарка — e-com PM.
5. Словарь типов входа / page_type и акционных категорий — e-com PM + маркетинг.
6. Единый channel_group для GA4, Zoho и отчётов — маркетинг.
7. Состав и дата релиза трекинга P1 — e-com PM + разработка.
8. Владелец sGTM / Consent Mode, стейдж-хосты, Product_Code в dataLayer — разработка + маркетинг.

## Что проверено и ограничения данных

- GA4 ↔ Zoho по номеру заказа в `transaction_id`: 97% наложки, 83% предоплаты; cookie GA есть у 96% чекаутов.
- WFP ↔ Zoho через `zoho_payments.Reference_id`: 99% транзакций.
- `view_cart.value` = цена последнего добавленного товара (проверка 15–20.09: совпадает с ценой последнего item в 59% событий,
  с суммой корзины — в 34%, ни одно не ≥ 2300 ₴). Сумма корзины считается по items; витрина 08 исправлена.
- GP по SKU (`fct_sku_revenue`) есть у 88% платных строк сентября; связка — название товара Zoho (`offer`), витрина 02 исправлена
  (строки инвойса называются «Дієтична добавка - "…" UA», в fct — «UA …»).
- `item_id` GA4 — внутренний id сайта: временный словарь на 36 позиций, нужен Product_Code (P2).
- Причины отказов при получении (Terminated) в Zoho не фиксируются; показ виджета (`upsell`) без location; купон приходит как `[object Object]`.
- `daily_kpi_metrics` за март–июнь содержит 6 дней в неделю (воскресенья без отгрузок) — на недельном графике такие недели не приглушены, приглушены только недели короче 5 дней.
- Витрины 01, 04–09 проверены на сентябре 2026; 02 — после исправления; 03 — когортная часть (GP-часть исправлена, целиком не прогонялась: дорого).

## Как обновить

1. Выполнить `sql/blocks/*.sql` в BigQuery (проект `perla-holistic-com`; через коннектор BigQuery в Claude или `bq query --use_legacy_sql=false`).
   Диапазон дат в запросах зашит (2026-01-01 … 2026-09-30 / 2026-10-07 для окна 7 дней) — сдвинуть при обновлении.
2. Сохранить результат каждого блока в `data/raw/<имя блока>.json` — либо ответ BigQuery API (`schema` + `rows`), либо `{"fields", "rows"}`,
   либо `bq --format=json`.
3. `python3 ecom/build.py` → `data/snapshot.json`, `template.html`, `index.html`.
4. Опубликовать `index.html` как обновление артефакта https://claude.ai/artifact/7RmB8prsCLmNS24dG1nnnv (тот же URL).
5. Проверка: `node` + Playwright скрипт из сессии (все вкладки, 400 px, тёмная тема) или просто открыть страницу и пройти вкладки.

Ежемесячная рутина Cockpit (1-е число, 10:47 Киев) может запускать и этот сбор, когда определения будут согласованы.
